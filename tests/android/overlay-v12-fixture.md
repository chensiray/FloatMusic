# Android 1.2 overlay fixture

`run-overlay-v12-contract-test.ps1` compiles all native production Java, the local Qt bindings, and the 1.2 / 1.1 / 1.0 / 0.9 overlay fixtures against API 36 and Java 8. The four new JVM groups exercise duplicate queue occurrences, absolute reorder destinations and stale order rejection, full source identities in copied next/tail payloads, custom 1–180-minute validation, native sleep status derivation, and history source/time captions. The existing eleven contract groups remain regressions for source selection, independent quality requests, volume, lyrics and spacing. No device or network is used.

`run-overlay-v12-ui-test.ps1 -CompileOnly` compiles production dependencies and the real-view instrumentation without building an APK or touching a device. `run-overlay-v12-ui-test.ps1 -DeviceSerial <serial> [-AdbPort 5038] [-Screenshots]` requires the rebuilt 1.2 target, overlay permission and matching Android debug key. It builds and installs only `org.floatmusic.v12uitest`, runs ten scenes, stores the result in `artifacts/v12-android-ui/device`, then removes the separate test package. The runner requires every named scene, the exact passed count, successful instrumentation and `uiPassed=true`; a partial run cannot pass.

The instrumentation class is `org.floatmusic.player.OverlayV12UiTest`, so its test-only service subclass can record the package-level playback dispatch boundary. Actual queue, history and timer mutations still use the real service and real isolated `PlaybackQueueStore`; `playQueueEntry` and `playHistoryTrack` are recorded without resolving audio, networking or starting a MediaPlayer. Production Java is compiled into a separate dependency directory and never packaged into the fixture APK. Each scene attaches a context with unique preferences and isolated files, cache and no-backup directories; no service `onCreate` is invoked, and `destroyed=true` prevents notification/publication work. Cleanup closes the fixture overlay, removes its handler callbacks and shuts down its executor.

The ten scenes cover More navigation, separate duplicate queue rows and occurrence playback/removal, confirmed clearing, tap sorting and stale-menu rejection, real drag auto-scroll plus preservation during snapshot updates, history source/time/replay/next/clear, local/search/online next/tail menus, timer presets/end-current/cancel/header status, validation and custom draft identity during ticks, notification expansion into the existing vertical volume popup, and queue scrolling/paging in a short dark card at the maximum available scale. Existing scale settings remain 90–130%; this scene requests 130% and permits the screen-width clearance to constrain the actual scale further. It checks the measured window width and height against the available viewport and reaches the final queue page. Drag policy is exercised through the same production `DragReorder` object and final commit used by Android drop events; the final device review also checks an actual long-press gesture.

With `-Screenshots`, scene images are written only to the target cache subdirectory `v12-ui-fixture`. The 1.1 UI fixture remains the accepted lyric font 10–30sp, line spacing 0.8–3.0, per-source quality, volume and draft regression. The 1.0 and scroll fixtures remain unchanged. Device execution and APK installation are coordinated by the primary integration agent after the matching target build.
