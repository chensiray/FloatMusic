# 1.8 Library Organization Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans and parallelize independent implementation and verification. Steps use checkbox syntax.

**Goal:** Ship a Windows and Android preview with library filtering, batch local imports, artist browsing and current-track navigation.

**Architecture:** Retain the existing Qt controller and Android bridge, playlist store, and cache index. Add artist browsing as independent network state. Keep playlist and queue row identities stable while filtering or jumping.

**Tech Stack:** C++17, Qt Quick and Android Java.

## Scope

- [x] Add a name/artist query and offline-only filter to saved playlists, including Favorites. Derive offline availability from local imports and completed usable cache entries. Keep playback and mutation bound to original track identities.
- [x] Extend the existing local audio picker to accept multiple selections on both platforms. Reuse existing validation and retain successes when individual inputs fail. Report aggregate outcomes.
- [x] Add artist search using supported public catalog endpoints. Show source, available profile description and playable works. Keep requests separate from playback and song/playlist search. Clearly indicate unavailable data.
- [x] Mark the loaded song in song lists and the exact active entry in queues. Add an accessible arrow that reveals it, including across Android pagination. A playlist filter can be cleared when it hides the current song.
- [x] Verify filtered actions, duplicate queue entries, offline changes, import partial success, artist request lifecycle and translated UI. Build the two 1.8 preview packages without publishing.
