# 浮音 1.5：悬浮窗体验

用户要求：双端提供独立悬浮歌词的高亮／最边缘透明度设置，中间逐级变化；修复手机开启页“退出浮音”无反应；其他悬浮窗体验细节交由实现者调整，并自行验收。

沿用 Qt Quick/C++ 与 Android 原生 Java，不改变 1.3/1.4 既有主体布局和虹彩风格，保留本地尚未提交的 1.4 审查修复。用户已授权直接实施及自行验收，设计细节由实现者决定，不再额外安排选择／审批轮次。

## 方案与取舍

只调整个窗口透明度无法分别控制当前句和外围句；给每一行独立设置会增加操作负担。采用两端可见度控制，在既有歌词设置内增加两条滑杆，按距离插值，显示百分比并立即保存。可见度文案明确“100% 最清晰，0% 完全透明”，避免“透明度 100%”歧义。

实现者决定：当前句 10–100%，边缘句 0–当前句%，默认 100%／35%；当前句降低到边缘以下时同步约束边缘，防止中心比外围更淡。对 1/3/5/7/9 行，边缘定义为最外侧完整显示行；1 行时只应用当前句、禁用边缘滑杆。中间按距离线性过渡，超出最外侧行的动画守卫行继续向零淡出。不修改字号、高亮颜色和跟随节奏。

## 操作细节

- 两端提供位置锁定和一键居中；Windows 既有锁定增加持久化和设置入口，Android 补齐锁定。
- Windows 歌词右键可居中；手机长按歌词仍能进入设置，锁定不妨碍打开设置。
- 透明度调整只更新绘制，不重建文字位图、不打断正在运行的歌词跟随动画；不可见边缘不留下触摸阻挡。
- 只让文字范围接收输入，留白点击穿透；不因增加操作控件扩大常驻歌词点击区。
- 设置沿用现有页面滚动和至少 44/48 像素操作高度；中英文即时切换，浅深色均可读。
- 退出走原生主线程，先保存播放现场、停止服务，结束 Activity／任务；即使服务从未启动也必须有效。避免只请求 Qt 事件循环退出而保留开启页。

## 验收

验证边界值、1/3/5/7/9 行、过渡连续、设置重启保持、靠边／小屏、锁定和找回位置、透明边缘穿透。退出检查无服务／有服务、重复点击、安全保存及重新打开。运行桌面全量、Android 设备无关和真实原生窗口测试，检查截图，构建完整 Windows 与 ARM64 安装包。真实手机不在时使用隔离模拟器验证原生路径，并明确完整 ARM64 应用的真机覆盖限制。

不发布远端、不变更在线音源协议、不加入 1.5 以外新功能。
