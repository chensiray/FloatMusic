# 浮音 1.6：音乐与歌词离线缓存

## 目标与范围

Windows 与 Android 同步提供歌曲音频、原文歌词、译文歌词的本地缓存，支持应用重启后断网播放，并在统一页面管理。沿用现有布局、语言适配、播放队列和悬浮歌词。用户已选择“手动保存长期保留，自动缓存按容量清理”。

## 方案选择

1. 仅手动保存：存储行为可控，但每首离线歌曲都需提前操作。
2. 仅自动缓存：操作少，但不能保证喜欢的歌曲长期保留。
3. 两类并存（用户选择）：手动项目受保护，自动项目受容量限制。两类共用文件与索引，已有自动缓存可以转为长期保存，无需重新下载。

## 默认策略（用户已于 2026-10-29 确认）

- 自动缓存默认开启；Android 默认仅 Wi-Fi 下自动缓存。手动缓存走用户明确发起的下载，不受自动缓存的 Wi-Fi 限制，界面说明其可能使用移动流量。
- 自动缓存容量默认 1 GB，提供 256 MB、512 MB、1 GB、2 GB、5 GB 选择；可关闭自动缓存。
- 手动保存不计入自动缓存限额，但计入总占用；不会因自动清理而删除。
- 自动缓存最久未使用的条目优先清理；正在播放、正在写入或已转为手动保存的项目不参加自动清理。
- 自动任务单文件超过限额、未知长度写入达到限额或受保护项目使剩余空间不足时，停止该任务并显示容量不足，不强删受保护项目，也不突破自动缓存限额。手动任务不受此限额约束，但仍须检查磁盘空间。
- 关闭自动缓存停止未完成的自动任务，已完成内容仍可离线播放；手动任务继续执行。
- 文件保存在应用专用数据目录。第一版不提供自定义存储目录、音频导出或跨设备同步。

## 入口和管理页面

- 单曲菜单新增“保存到本地”；已自动缓存歌曲可直接“长期保留”。当前歌曲也有同等入口。
- 本地歌单详情提供“缓存歌单”；在线歌单详情提供“缓存已加载歌曲”，明确显示实际加入任务的歌曲数，不把未加载的歌单部分误称为整张已缓存。
- 设置新增“本地缓存”二级页，包含自动缓存开关、容量、手机仅 Wi-Fi 开关和统一管理入口。
- 管理页显示总占用、手动保存与自动缓存分别占用、任务状态与进度；可筛选全部/手动/自动。
- 每项展示曲名、歌手、音质、文件大小、歌词状态；支持直接播放、长期保留、取消、重试、删除。
- 提供“清理自动缓存”和“清空全部”。批量删除前说明范围、数量与占用；清空全部需明确确认。删除只移除应用管理的缓存，不删歌单记录或用户导入的源文件。
- 当前播放项目的删除采用延后清理，等该文件不再使用后释放，不中断正在播放的歌曲。

## 下载、持久化与错误

- 音源仍经现有解析器获取可播放地址，缓存不是保存临时 URL，而是下载完整音频。只有应用能够取得的完整音频才可缓存；不处理加密文件解密。
- 缓存键包含平台、歌曲标识和音质，保存实际音质与格式，避免不同平台同名歌曲混淆或把低音质标成高音质。
- 去重任务、限制同时下载数量；流式写入临时文件，检查 HTTP 状态、预期长度、非空内容及基本媒体有效性，完成后原子提交索引和正式文件。错误页面与未完成文件不能标记为可离线播放。
- 对未知长度下载显示不定进度，不虚报百分比；下载中断、取消、存储不足均清理临时内容并给出可重试状态。
- 第一版中断后从头重试，不做跨进程断点续传；重启后恢复待处理状态，不把中断任务当作成功。
- 主动退出应用后下载停止，下次启动按原类型及网络策略恢复待处理任务；第一版不承诺退出后持续下载。
- 元数据包括原平台标识、曲名、歌手、专辑、时长、音质、文件与歌词状态、保存类别、大小和最近访问时间。
- 歌词独立存储原文与译文及“纯音乐/无歌词”状态；音频成功而歌词失败时明确提示，可单独补取歌词，已缓存音频仍可用。
- 歌词原文与译文分别区分未知、失败、已确认无内容、有内容。仅凭空字符串不永久标记为无歌词，只有明确来源响应才标记纯音乐。
- 启动时检查索引与文件是否一致；文件丢失或损坏后不继续展示为可离线，允许联网后重新缓存。

## 播放接入

- 播放歌曲时优先匹配本地缓存，命中后不依赖在线解析器或在线歌词请求。
- 当前选择音质没有缓存但存在其他已保存音质时，允许使用可用缓存并明确显示实际音质，避免断网时无法播放已有内容。
- 缓存管理页、原歌单和播放队列都能进入同一离线播放路径，保持歌曲身份、历史和歌词偏移。
- 自动缓存从实际成功播放的在线曲目启动，后台完整下载，不阻塞起播；“听过”不等于“已完整缓存”，以管理页状态为准。
- Android 需同时接入原生 PlaybackService 的媒体路径与 Qt 提供的歌词状态，防止只缓存了音频但后台悬浮歌词仍依赖网络。
- 本地文件已损坏时撤销可用状态：联网可重取，离线明确报错，不无限重试。

## 模块边界

- 桌面新增缓存存储与下载模块，负责目录、索引、任务、限额和清理；PlayerController 负责播放及歌词接入；QML 负责入口、进度与管理。
- Android 新增对应缓存模块，PlaybackService 负责服务生命周期、实际播放与状态通知；OverlayWindow 显示原生管理界面，Qt 桥接歌词及设置。
- Android 缓存索引和文件只有 Java 模块负责写入；Qt 通过桥提交或读取歌词。服务恢复后可直接恢复本地歌词，不能等在线请求完成。下载使用独立执行器和取消状态，不复用承载切歌解析的单线程 importer。
- 实际文件按平台、歌曲与实际音质去重，并保存请求音质到实际音质的映射。缓存播放继续提供时长、音质、格式和原平台身份，不能因走本地路径而显示为 standard 或丢失历史关联。
- 使用现有 Qt/C++、Android Java 与本地 JSON 持久化，不引入新的服务端或第三方下载框架。

## 验收标准

1. 在线缓存音频和双语歌词后退出应用，在禁止测试服务器访问的条件下重启并播放、拖动进度、上一首/下一首，歌词仍同步。
2. 断网未缓存、仅有音频、无歌词、原文/译文缺失、不同平台同名歌曲、不同音质都有准确状态。
3. 超限只清理自动项目；手动保存、当前播放、正在下载的项目不会被误删。
4. 中断、取消、响应错误、内容不完整、磁盘不足、重启、损坏索引与丢失文件均不产生假成功。
5. 任务去重、自动转手动、关闭自动缓存、Wi-Fi 约束、批量删除范围可验证。
6. 双端中英文、明暗模式、手机窄屏、长曲名和多任务列表可操作；下载不阻塞播放或歌词滚动。
7. 生成双端验收包；实体手机安装前确认连接设备，功能自动化使用隔离数据，不清理用户现有歌单和缓存。
