# 1.5.0-preview.3：桌面歌词空行与清晰度

## 范围与原因

Windows 桌面歌词和 Android 独立悬浮歌词同步优化。原来带时间戳的空白内容仍占据一行：Windows 显示音符或空白，Android 隐藏文字但保留位置。现在在各自显示层过滤空行，不改变播放器的原始歌词、复制内容和时间轴。

- 清理空字符串、纯空白、零宽空格、BOM，以及同一条歌词里的空白段落。
- 原文为空而译文有效时显示译文。
- 保留有效行的时间戳；空白间奏期间停留在上一有效行，到下一有效时间戳再滚动。首句前不提前高亮，结尾空白不产生新的一行。
- 首尾为了让当前句保持居中而预留的透明空间仍保留；不复制歌词填满窗口。

## 视觉选择

参考 [SPlayer 桌面歌词的字体、字号、颜色设置](https://splayer-next.imsyy.top/guide.html)和 [MusicBee 桌面歌词插件的描边渐变方案](https://github.com/Liyucheng1997/317_plugin-MusicBee-DesktopLyrics)。采用字形和描边强化可读性，沿用浮音紫色强调；没有引入整块背景或昂贵的实时模糊。

- Windows 使用微软雅黑 UI，普通行半粗、当前行加粗；Android 普通行 medium、当前行 bold。
- 浅色模式为深色字、深紫高亮、白色描边；深色模式为白字、浅紫高亮、深色描边。描边本身不再额外降低透明度。
- 行间透明度改为二次曲线：靠近中心保留更多可见度，接近边缘时逐渐下降。用户设置的中心和边缘端点保持准确。
- 最外围字号缩放下限从 76% 提高到 94%，当前句继续略微放大。
- 新设置默认边缘可见度 55%；已有透明度设置不覆盖，可以到“设置 → 桌面歌词”调节。
- 保留缓存文字位图与单绘制层，不在 Android 动画帧中重新排版或生成位图。

## 验证

2026-10-28，本机验证记录位于 `artifacts/v1.5.3/`，Android 原生测试截图另位于 `artifacts/android-lyric-jump-2026-10-20/`。

- 修复前 Windows 空行用例失败：3 行有效内容却生成 6 行；Android 同样以真实窗口用例复现失败。
- 修复后 Windows 全部 CTest **14/14** 通过；原生窗口专项 **6/6**（含初始化和清理）通过，覆盖空行、透明度、1/3/5/7/9 行、明暗主题、拖拽、穿透、持久化、纯文本。
- Windows 原有居中测试以固定 420ms 等待窗口刷新，在已发布版和本次版本的原生后端均可能过早断言。改为有 3 秒上限的实际位置等待；未对生产居中逻辑做试探性修改。
- Android 隔离模拟器两批专项 **10/10、5/5** 通过（空行用例重复一次），覆盖空行、无动效/有动效滚动、透明度、缓存、拖动、锁定、跨应用穿透、九行和明暗背景截图。
- Android 3 行与 9 行滚动：绘制间隔 p95 约 **18.6ms / 18.5ms**，超过 32ms 的绘制间隔均为 0；逐帧窗口移动与布局次数均为 0。模拟器数据不等同于所有实体手机表现。
- Android 设备无关规则测试通过，包括非线性渐隐端点、对称性、连续性、不可见字符与时间定位。
- 已检查 Android 亮、暗背景以及 Windows 两种主题截图。真实桌面背景变化较大，明暗主题和可见度仍由用户选择。

版本为 `1.5.0-preview.3`，Android versionCode 为 26。本次生成本地验收包，未发布到 GitHub。
