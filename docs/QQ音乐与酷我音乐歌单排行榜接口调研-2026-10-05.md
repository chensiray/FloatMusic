## QQ：请求、返回字段与边界

### 网关与匿名条件

当前 `simple-music` 将 QQ 请求发到 `POST https://u.y.qq.com/cgi-bin/musicu.fcg`，JSON 信封包含请求块的 `module/method/param`。通用头是 `Referer: https://y.qq.com/` 和浏览器 UA；它的请求函数仅当 `opts.cookie` 且 Cookie 非空时才发送 Cookie。`GetRecommendFeed` 调用不要求 Cookie；公开关联歌单甚至明确传空 Cookie 和 `uin:'0'`。[请求封装][simple-request]、[推荐歌单实现][simple-feed]、[关联歌单实现][simple-related]

最新 `L-1124/QQMusicApi` 的 `cgi_endpoint` 默认 `sign=False`、`require_login=False`；本报告的 `songlist.get_detail`、`top.get_category/get_detail` 没有改成登录或签名请求。写歌单接口则明确 `require_login=True`。这是**库的请求标注**，实际匿名可用范围仍以上面的接口返回为准，不能推广到私人歌单和音频解析。[端点默认值][qq-endpoint]、[歌单读写模块][qq-songlist]、[榜单模块][qq-top]

QQ 最新库的 `search_by_type` 已固定 Android 平台和 `DoSearchForQQMusicMobile`；本轮成功探测的是 Desktop 方法，不能混用两个响应模型或将 Android 客户端会话条件自动套到 Desktop 请求。浮音 0.9 的 QQ 歌曲搜索实际仍走 Vkeys，尚未直连这个内部搜索模块。[最新搜索模块][qq-search]、[Desktop 搜索实现][simple-search]、[浮音歌曲搜索](../src/musicapi.cpp#L237)

### 公开歌单详情与分页

已验证的详情路线为 `music.srfDissInfo.DissInfo/CgiGetDiss`。当前源码直接给出了下列参数和返回映射；实测使用 `song_num=3`、偏移 `0/3`，下例的 100 为建议常规页大小，并非本次实测了 100 首页。[QQ 歌单模块][qq-songlist]、[详情返回模型][qq-model-songlist]、[项目当前分页实现][simple-diss]、[详情运行证据][runtime-phase2]

```json
{
  "disstid": 7593082970,
  "dirid": 0,
  "tag": true,
  "song_begin": 0,
  "song_num": 100,
  "userinfo": true,
  "orderlist": true,
  "onlysonglist": false
}
```

| 含义 | 原始字段 |
| --- | --- |
| 标题、简介、创建者 | `dirinfo`；基础模型兼容 `title/dissname/name/dirName`，`desc/description`；创建者为 `creator.nick` 等详情字段，以实际响应为准 |
| 本页歌曲、条数 | `songlist`、`songlist_size` |
| 全部歌曲数 | `total_song_num`，不能拿 `songlist_size` 代替总数 |
| 是否还有下一页 | `hasmore`；下一次递增 `song_begin`，库使用 `num*(page-1)` |
| 稳定曲目身份 | 每项 `mid`；数值 `id` 另外保留，不代替 `mid` |

应按原始返回条数推进偏移，保留原始排序；在规范化之后去重或丢弃无效项，不应按过滤后的条数推进偏移。遇到空页、明确结束标记、总数已取得、重复页或读取上限时停止，并报告未读完的范围。这是依据源接口的 offset 分页与浮音现有 2000 首上限提出的适配建议，不是上游承诺。[QQ offset 分页][qq-songlist]、[浮音上限](../src/musicapi.cpp#L18)

旧 `fcg_ucc_getcdinfo_byids_cp.fcg` 仍可从 LX 看见，并在失败时回退 `CgiGetDiss`；它旧版流程把 `songlist.length` 当总数。`simple-music/docs/qq-music-api.md` 也仍写“旧 fcgi 一次返回全部曲目”，但当前 `qq-client.ts` 已切到 `CgiGetDiss` 分页循环，**应以当前固定提交的实现优先**。[LX 旧/新详情分流][lx-tx-songlist]、[项目旧描述][simple-api-doc]、[项目当前分页][simple-playlist]

### 榜单目录与榜单歌曲

目录请求 `music.musicToplist.Toplist/GetAll` 的 `param={}`，响应 `data.group[]`；每组 `groupId/groupName/toplist[]`。榜单摘要有 `topId/title/intro/period/updateTime/totalNum/frontPicUrl`。摘要内的 `song[]` 是预览，只有数值 `songId` 等字段，不能冒充完整、可交给 0.9 播放链路的 MID 曲目列表。[QQ 目录/详情模型][qq-model-top]

详情请求同模块 `GetDetail`，参数 `topId/offset/num`，可带 `withTags:true`。响应请求块的 `data.data` 是榜单信息，`data.songInfoList` 是完整歌曲，`data.data.totalNum` 为榜单总数；offset 按 `num*(page-1)`。榜单不是 `disstid` 歌单，必须通过独立 `kind=ranking` 分流。[QQ 榜单模块][qq-top]、[当前项目榜单分页][simple-top-detail]

本次实时目录给出的热歌、新歌、飙升 ID 分别为 `26/27/62`。`tamnd/qqmusic-cli` 固定提交仍用旧 v8 endpoint 与 `hot=4,new=26,rising=27`，且 `charts` 只是硬编码表；它证明源码发的是无 Cookie GET，不证明这些标签、ID 和今日新目录相同。接入应使用 `GetAll` 的实时 ID；旧项目作为独立旧协议参考。[旧匿名 v8 客户端][qq-cli]

| 推荐歌单 | `wapi.kuwo.cn/api/pc/classify/playlist/getRcmPlayList`：`loginUid=0/loginSid=0/appUid`、`pn`、`rn`、`order=hot/new` | `data.data[]`、`data.total/pn/rn`；条目 `id/digest/name/uname/total/desc/img/listencnt`；这里只证明 `loginUid=0` 的匿名请求，不是账号登录 |
| 普通用户歌单详情 | `nplserver.kuwo.cn/pl.svc`：`op=getlistinfo`、`pid`、`pn=page-1`、`rn`、`encode=utf8`、`keyset=pl2012`、`identity=kuwo`、`pcmp4=1`、`vipver/newver` | `result="ok"`，`title/info/uname/pic/playnum/total/rn/musiclist[]`；曲目 `id/name/artist/album/duration/N_MINFO` |

搜索响应的 `rformat=json` 名称不能保证是标准 JSON。LX 当前用 `objStr2JSON` 替换单引号；本次先保留严格 JSON 解析失败，再用 `ast.literal_eval` 安全解析字面量对象，不执行响应内容，两个请求页都成功得到 `abslist`。这仅验证了本次返回的字面量格式，不证明能处理所有未来格式。浮音最终实现需要有界、按字符串转义规则处理、经过结构校验的兼容解析，不能使用 JavaScript `eval`、盲目替换所有引号或把网页错误正文当列表。[LX 字符串解析函数][lx-kw-util]、[LX 搜索映射][lx-kw-songlist]、[原始解析失败][runtime-phase1]、[安全解析结果][runtime-phase2]

`digest` 是目录类型：LX 注释与分流把 `8` 当普通歌单、`5` 当分类目录、`13` 当专辑。推荐条目不是都能直接把 `id` 发给 `pid`；普通 `digest=8` 才走 `getlistinfo`，`digest=5` 先查 `qukudata` 的 `sourceid`，专辑另走 album 适配。本次样本 `3677150229` 的 `digest=8`，所以适合普通歌单详情核验。[LX 类型分流][lx-kw-songlist]

LX 单次详情 `rn=1000` 是客户端配置，不是服务器保证。浮音建议沿用 100 首左右的有限分页、最多 2000 首的边界，并对实际 `rn/total/musiclist.length` 作核验；单页上限和超过上限时的行为尚待探测。[LX 配置与分页][lx-kw-songlist]、[浮音读取边界](../src/musicapi.cpp#L18)

### 酷我榜单：目录与歌曲分离

LX 当前 `kw/leaderboard.js` 保留 `qukudata.kuwo.cn/q.k?op=query&cont=tree&node=2&...` 的目录读取函数，但 `getBoards()` 中调用已注释，实际直接返回 43 张静态 `boardList`。旧 `kbangserver.kuwo.cn/ksong.s` 地址也只是注释，不能称为当前 LX 真正在用的歌曲请求。本轮 WWW 动态目录失败时，静态目录可以提供有限候选名称，但必须标为内置候选，并用歌曲详情验证 ID 是否仍存在。[LX 当前榜单分流][lx-kw-board]

当前歌曲详情为 `GET https://wbd.kuwo.cn/api/bd/bang/bang_info`。**没有用户账号 Cookie，但有固定客户端协议**：[LX 请求构造][lx-kw-board]、[LX `wbdCrypto`][lx-kw-util]

```json
{
  "uid": "",
  "devId": "",
  "sFrom": "kuwo_sdk",
  "user_type": "AP",
  "carSource": "kwplayercar_ar_6.0.1.0_apk_keluze.apk",
  "id": "16",
  "pn": 0,
  "rn": 100
}
```

请求参数对象直接序列化为 JSON，不包 `request`。源码将其 AES-128-ECB 加密、Base64，再构造 `data/time/appId/sign` 查询参数；`sign=MD5(appId+Base64密文+Unix毫秒).toUpperCase()`。响应 URL 解码、Base64 解码、AES 解密后才是 JSON；成功条件包括 HTTP 200、业务 `code=200` 与 `data.musiclist`。固定算法参数是该开源客户端内置的协议常量，不是用户会员或应用合作凭据。本次使用系统已有的 .NET AES 验证此协议，没有安装依赖；三张主要榜单与热榜第二页实际成功。此路线维护成本仍高于普通 JSON GET。[WBD 首次结果][runtime-wbd]、[WBD 连续页结果][runtime-wbd-pages]

同一源码及本次实测的主要 ID：热歌 `16`、新歌 `17`、飙升 `93`。返回元数据包含 `data.name/info/pic/releaseDate/total` 与 `data.musiclist[]`；项 `id/name/artist/album/duration/pic/n_minfo`。分页 `pn=page-1`、客户端常规 `rn=100`，本次仅验证 `rn=3`。静态表还包括“会员畅听榜”等标签，读取榜单名称或曲目仍不表示歌曲可匿名播放；本次接入结论只覆盖元数据。[LX 榜单 ID 与歌曲映射][lx-kw-board]、[实际 WBD 元数据][runtime-wbd]

### 酷我 musicrid / RID 接入 0.9

| 返回形式 | 规范化 |
| --- | --- |
| WWW `musicrid="MUSIC_数字"`、旧歌曲搜索 `MUSICRID` | 仅去掉精确的 `MUSIC_` 前缀，并验证余下为正十进制字符串 |
| WWW `rid`、`nplserver.musiclist[].id`、`wbd.musiclist[].id` | 转字符串并验证为正十进制 RID，不使用 JavaScript 浮点重新生成大整数 |
| LX 内部统一字段 `songmid` | 在酷我模块中值仍是数字 RID，不能因为名称是 `songmid` 就按 QQ 字符串 MID 处理 |
| 0.9 目标身份 | `source="kuwo"`、`songId=RID`、`id="kuwo:"+RID`；播放/歌词交给现有 Ourcraft 路径 |
| 曲目字段 | `name`、`artist`（HTML 实体按纯文本解码）、`duration`（秒）；保存元数据，避免 Ourcraft 的单曲“未知”名称覆盖它 |

依据：[LX 歌曲搜索 `MUSICRID` 映射][lx-kw-search]、[歌单/榜单 RID 映射][lx-kw-songlist]、[榜单映射][lx-kw-board]、[Ourcraft 当前酷我 provider][ourcraft-kw]、[浮音平台 ID 校验](../src/musicapi.cpp#L27)。

## 与现有浮音 0.9 的适配关系

现有 `MusicApi` 已有按 `source` 的歌曲搜索、解析和歌词方法，QQ 为 Vkeys/INJAHOW，酷我为 Ourcraft；但 `searchPlaylists(query)`、`fetchRankings(done)`、`fetchPlaylist(id,done)` 仍没有平台参数，直接使用网易云 `type=1000`、`/toplist` 和 `/playlist/detail`，歌曲补全也固定网易云详情。这些函数不能只换域名就取得 QQ/酷我歌单。[当前接口声明](../src/musicapi.h#L34)、[网易云歌单搜索](../src/musicapi.cpp#L281)、[当前榜单与详情](../src/musicapi.cpp#L314)

建议后续实现的最小变化是：

1. 歌单/榜单摘要增加 `source`、`kind`（`playlist` 或 `ranking`）、`resourceId`；内部唯一键例如 `tencent:playlist:7593082970`、`tencent:ranking:26`、`kuwo:playlist:3677150229`、`kuwo:ranking:16`。这是建议的新容器身份，不改变已有曲目 `tencent:MID/kuwo:RID`。
2. QQ 目录走 `GetAll`，榜单详情走 `GetDetail`，公开歌单走 `CgiGetDiss`；各自检查外层、请求块和业务错误，再规范化元数据。优先沿用本次成功的 Desktop 歌单搜索。
3. 酷我 PC 推荐/关键词搜索、普通 `digest=8` 歌单详情独立适配；三张已验证的 `wbd` 榜单可加入候选，配置中保留清晰的来源。其它静态榜单尚未全部核验，动态目录暂不能承诺完整实时性。
4. 页码、偏移、原始位置、去重与结束条件统一到现有 2000 首读取上限；简介做纯文本处理，未知总数与 0 首分开。保留单页失败和未取得完整歌单的提示。
5. 曲目直接带平台身份交给 0.9 解析器；QQ 数值 `songid`、`media_mid` 和酷我 `MUSIC_` 字符串不可误当网易云 ID。导入、收藏、排序和重启恢复应分别核验 Windows/Android。

QQ 的 `updateTime` 与 `period` 在当前返回模型中是字符串，现有网易云榜单映射的 `updateTime` 则读取整数；后续应保留平台展示文本或明确解析格式，不能直接当毫秒时间戳。详情模型中的 `songlist_size` 也只是本页条数，应优先用 `total_song_num`。[QQ 榜单模型][qq-model-top]、[QQ 歌单模型][qq-model-songlist]、[现有榜单时间读取](../src/musicapi.cpp#L339)

上述是依据本次源码与元数据样本提出的实现方案，不代表已修改程序或已通过双端端到端测试。当前 `get()` 是 GET 且 Cookie 手动禁用、15 秒默认超时、2 MiB 响应上限；QQ JSON POST、酷我非标准文本及 AES 响应都需要新的有界请求/解析能力，不能无条件扩大现有所有请求的权限或限额。[现有网络读取](../src/musicapi.cpp#L160)

Windows QML 调用 `libraryAction`；Android 浮窗发送同名操作，两端在线歌单最终共用 C++ 的 `PlayerController::libraryAction`（定义在 `playerlibrary.cpp`）与 `MusicApi`。扩展平台元数据适配及操作参数即可复用这条路径，不需要把歌单接口复制进 Android `AudioResolver`。[QML 调用](../qml/Main.qml#L114)、[Android 操作发送](../android/src/org/floatmusic/player/OverlayWindow.java#L164)、[C++ 共用入口](../src/playerlibrary.cpp#L45)

0.9 的 `PlaylistDocument` 已能解析与导出 `local/netease/tencent/kuwo` 混合曲目及 `id/source/songId/name/artist/path`，因此本次元数据扩展无需重做混合本地歌单 JSON 格式。QQ/酷我在线分享链接的解析可以独立增加；已有纯数字在线 ID 仍只表示网易云歌单，不能无平台信息猜测成 QQ 或酷我。[现有 JSON 身份校验](../src/playlistdocument.cpp#L47)、[现有导出字段](../src/playlistdocument.cpp#L86)、[当前在线链接解析](../src/playlistdocument.cpp#L20)
