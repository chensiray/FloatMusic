## 核心逻辑与请求开销

扩展审查确认并修复以下 4 项问题：

1. **P2：失败切歌后漏记保留媒体的首次播放历史。** 导入 A 并暂停，选择缺失的 B，再播放仍保留的 A，原代码的共用待记标记被 B 清掉。现在将待记历史归属于已加载媒体，暂停／继续不会重复记录。回归：`failedSelectionKeepsUnplayedRetainedAudioHistory`。
2. **P2：清空队列后旧请求重新填回队列。** 歌单选曲或本地导入尚未完成时清空，迟到结果仍替换队列。现在撤销待处理选择和导入；正在播放的媒体继续，迟到导入副本会清理。回归：`clearQueueCancelsPendingPlaylistSelection`、`clearQueueCancelsPendingLocalImport`。
3. **P2：酷我备用音源接受明确冲突的歌曲 ID。** 请求 42 而响应声明 43 时，原桌面路径仍可能使用该音频。现在在访问音频前拒绝冲突，兼容响应未提供 ID 的旧服务。回归：`kuwoBackupRejectsConflictingIdentity`，覆盖原址／中转、字符串／数值 ID 和兼容情况，共 10 行数据。
4. **P2：改看新歌单后，旧歌单仍继续详情补全或分页。** 之前只丢弃最终结果，却继续进行无用网络请求。现在给浏览请求传入独立有效性检查，在响应解析和下一批请求前停止旧流程；主动导入不受浏览切换影响。回归：`obsoletePlaylistBrowsingStopsFurtherRequests` 的网易／酷我 × 首次详情／后续读取 4 个场景，以及 `playlistImportContinuesWhenBrowsingChanges`。

合计 8 项唯一问题；Standards 与 Spec 共有的原文显示问题只计一次。

## 性能测量

同一硬件加速 Android 模拟器，九行短句、连续 80 次横向 MOVE，移动保持在无需缩小文字的范围：

| 指标 | 发布版本 | 修复后 |
| --- | ---: | ---: |
| 文字位图重建数量 | 1,440 | 0 |
| 80 次移动主线程处理合计 | 91.37 ms | 12.02 ms（完整回归为 13.48 ms） |

这衡量特定拖动操作的处理开销，不代表整个应用快了相同比例。靠边需要改变字号时仍按需生成位图。

完整原生回归的绘制间隔 p95：独立歌词 18.40 ms、九行 18.20 ms、播放器 17.84 ms、长双语播放器 18.11 ms；普通切句均在 320 ms 内结束，无文字内容高度重排，独立歌词动画期间没有逐帧原生窗口移动。

旧歌单请求的本地服务复现：网易原来累计 4 次请求，切换时只需 1 或 2 次；酷我原来累计 3 次，切换时只需 1 或 2 次。修复后停止继续读取。已经发出的单次请求仍由现有超时回收，此次没有增加主动中断连接的通用网络层。

本轮覆盖 Windows 编译／离线集成、Android 生产 Java 的设备无关测试、隔离模拟器的实际窗口和动画，以及 ARM64 集成构建。未连接或覆盖安装用户手机，未发起真实在线音源测试，没有重新验证厂商后台保活、蓝牙切换和所有 Android 版本。API 33 以下输入窗口回退分支主要经源码核查与既有测试，不能据此宣称所有手机均已实测。
