# 网易云 Lua 接口 Windows 实测报告

实测日期：2026-09-16（北京时间约 16:28—16:45）。

对照应用：浮音 0.3.0，Git 提交 `d507dbb`。来源：用户提供的 `音乐.lua`（原脚本未纳入仓库）。本轮仅新增独立测试代码与报告，没有修改生产程序、安装包、歌单或账号配置，没有上传 GitHub。

## 1. 结论

**脚本的大部分接口在本机能够使用，已取得真实数据并完成 Qt 音频解码、暂停、进度跳转和续播测试，可以据此开发浮音的独立直连接口适配器。但原 Lua 的请求与解析方式不能照搬，也不能仅将这些域名填入浮音 0.3 的兼容 API 地址框。**

最关键的实测发现：

1. 搜索、详情、歌词（含翻译）、歌单、榜单接口可用。
2. 普通播放外链有歌曲差异：一首可播，一首跳转 HTML 错误页。
3. 第三方五档均获得可解码音频，但此次 `hires` 与 `lossless` 是相同源文件规格，不能声称五档代表五种实际音质。
4. 脚本对第三方地址追加 `.mp3` 会破坏链接，样本从可播放变成 HTTP 403。
5. 推荐网页依赖 User-Agent：测试默认 UA 下失败，手机 UA 下成功提取 6 个推荐歌单。
6. 第三方服务出现过连续超时，不能把一次成功当作稳定性保证。

## 2. 测试环境与方法

- Windows 11、Qt 6.11.2、MinGW 13.1、Qt Multimedia / FFmpeg 7.1.5，与浮音的主要技术栈一致。
- 网络接口使用 `QNetworkAccessManager`；播放使用 `QMediaPlayer + QAudioOutput + QAudioBufferOutput`。
- 不登录网易云账号，不传 Cookie、不执行 Lua、不执行网页中的 JavaScript。
- 查询词“纯音乐”，每次请求 3 条；主要歌曲 `347230`《海阔天空》、`139774`《The truth that you leave》；翻译歌词样本 `4337372`《Yesterday (Remastered)》；榜单 `19723756`“飙升榜”。
- 播放测试静音；收到解码音频后播放约 0.8 秒，暂停 0.4 秒，跳到约第 10 秒，再验证位置增长。没有做整曲听感、长时间稳定性或 Android 验证。
- 分别记录 HTTP 状态、业务 code、必要字段、重定向、音频头及真实解码结果。没有把 HTTP 200 当作成功的唯一标准。

网络分轮记录：

| 结果文件 | 内容 | 说明 |
|---|---|---|
| `artifacts/api-probe/direct.json` | 首轮沙箱诊断 | API 多项成功；FFmpeg 被沙箱环境的 `127.0.0.1:9` 代理阻断，不用于判定音频源不可用 |
| `artifacts/api-probe/windows-live.json` | 沙箱外直连，26 项记录 | 普通外链、lossless、hires 播放通过；第三方前三档出现请求超时 |
| `artifacts/api-probe/quality-retry.json` | 五档音质对照，16 项记录 | Qt Network 显式使用本机已有 `127.0.0.1:7897` HTTP 代理，五档均通过；FFmpeg 媒体读取没有通过 QNetworkProxy 设置代理 |
| `artifacts/api-probe/diagnostics.json` | 补充直连，8 项记录 | 手机 UA、批量详情、HTTPS、无效 ID、翻译歌词 |

代理对照成功只能说明该轮网络路径可行；本次没有充分证据将前三档超时完全归因于代理或服务端。

## 3. 接口逐项结论

| 功能 | 脚本路径 | 实测结果 | 浮音接入要求 |
|---|---|---|---|
| 歌曲搜索 | `/api/search/get?type=1&s=...` | HTTP、HTTPS 均 200；返回 3 条、总数 272 | 可以接入；使用 URL 编码，读取 `result.songs`，保留服务总数 |
| 歌单搜索 | `/api/search/get?type=1000&s=...` | HTTP、HTTPS 均成功；返回 3 条、总数 554 | 使用独立歌单结果模型 |
| 排行榜 | `/api/toplist` | HTTP、HTTPS 均成功，返回 63 个榜单 | 推荐使用 HTTPS；榜单 ID 复用歌单详情 |
| 歌单详情 | `/api/v3/playlist/detail` | 业务 200；飙升榜 `trackCount=100`、`trackIds=100`，但 `tracks=10` | 必须补齐详情，不能只展示附带的 10 首就宣称完成 |
| 老版歌曲详情 | `/api/song/detail?ids=[...]` | 两首均成功，含名称、歌手和毫秒时长 | 使用服务时长；不要按文件大小/固定码率推算 |
| v1 歌曲详情 | `/api/v1/song/detail?ids=[...]` | 单首成功；两个 ID 一次返回 2 首 | 可按批补齐歌单，避免每首一个请求；更大批次上限未验证 |
| 原文歌词 | `/api/song/lyric` | 两首均成功，存在带时间信息的歌词字段 | 保留时间戳，用于同步歌词；不要在读取时删掉 |
| 翻译歌词 | 同上，`tv=-1&lv=-1` | Yesterday 样本原文 938 字符、译文 409 字符 | 双语展示可行；其他歌曲译文为空属于正常情况 |
| 推荐歌单 | `https://y.music.163.com/m/` | 默认测试 UA 被导向桌面首页，无 `window.REDUX_STATE`；手机 UA 保留移动页面，`Home.code=200`，6 条 | 请求需适配；HTML 结构不是稳定接口，必须容错；只解析 JSON，不能执行网页内容 |
| 普通音频 | `/song/media/outer/url?id=...mp3` | `139774` 成功；`347230` 返回错误页面 | 做内容和解码校验；不能承诺所有搜索结果都能播放 |
| 第三方播放解析 | `https://www.byfuns.top/api/1/` | 五种 level 最终均返回纯文本 URL、Range 206，且 Qt 播放通过 | 按纯文本 URL 解析，不按兼容 API JSON 解析；保留超时/不可用状态 |

这些都是当前网络、时间和样本下的结论，并非对全部曲库、账号状态或未来可用性的保证。服务内部如何取得音频、是否稳定提供完整或指定版本曲目，不能仅靠这些响应确定。

## 4. 音频结果

普通外链样本 `139774`：MP3，文件总字节 3,576,621；Range 返回 206；Qt 测得约 223.512 秒，可定位，解码、暂停、跳转、续播均通过。详情接口约 223.467 秒，与容器解码时长有约 45 毫秒差异，UI 播放进度应采用播放器时长。

第三方使用同一首 `347230` 对照：

| 请求 level | 实际识别 | 文件大小（字节） | 播放/暂停/跳转/续播 |
|---|---|---:|---|
| standard | MP3，128 kbps | 5,217,010 | 通过 |
| higher | MP3，192 kbps | 7,825,493 | 通过 |
| exhigh | MP3，320 kbps | 13,042,460 | 通过 |
| lossless | FLAC，44,100 Hz、16 bit、双声道 | 32,511,640 | 通过 |
| hires | FLAC，44,100 Hz、16 bit、双声道 | 32,511,640 | 通过，但未得到更高规格音频 |

`lossless/hires` 的 CDN 音频资源路径相同（临时签名不同），STREAMINFO 规格相同。应显示“请求 Hi-Res，实际 FLAC 44.1 kHz/16 bit”，不能直接显示“Hi-Res 已生效”。测试不是对音频母带来源或有损转码历史的鉴定。

两项容易误判的细节：

- FLAC 响应的 HTTP Content-Type 仍为 `audio/mpeg`；文件头为 `fLaC`，解码器也确认为 FLAC。不能只按 MIME 或文件名判音质。
- FLAC 样本约 31.0 MiB，超过现有本地导入的 30 MiB 上限。在线流播放与本地导入大小限制需要分别设计；若以后添加下载/缓存，不应悄悄绕过用户可见的本地导入规则。

## 5. 已验证的失败与边界

1. **普通外链的假成功**：`347230` 最终地址为 `https://music.163.com/404`，HTTP 仍是 200，正文是 HTML，无法当音频使用。不能仅由此断定具体原因是会员、版权还是该外链不开放。
2. **追加扩展名错误**：第三方 `standard` 返回的原始 URL 可 Range 读取并播放；原样尾部追加 `.mp3` 后返回 403。浮音必须保持 URL 原样。
3. **无效歌曲 ID**：v1 详情查询 `[0]` 返回 HTTP 200、业务 code 200、空 `songs`。要显示“未找到歌曲”，不能访问数组第一项导致错误。
4. **无效歌单 ID**：`id=0` 返回 HTTP 200，但业务 code 404，消息“歌单不存在”。业务状态必须单独判断。
5. **推荐网页客户端差异**：默认测试 UA 不可解析，手机 UA 可解析。只能判定脚本解析依赖环境，不能笼统宣布该 URL 已失效。
6. **第三方网络波动**：直连轮 standard/higher/exhigh 各约 12 秒超时，其他轮能够成功；需要有明确错误、有限重试和取消。
7. **不应把沙箱失败当产品缺陷**：首轮 FFmpeg 明确报告连接 `127.0.0.1:9` 失败。沙箱外同类播放成功，无需为此修改浮音播放器。

## 6. 对浮音后续实现的具体建议

推荐保留现有可配置兼容 API，新增“Lua 直连来源”适配器，不把两个协议混成一个 base URL：

- 直连元数据：HTTPS 搜索、详情、歌单、榜单、歌词。
- 音频地址解析：将普通外链和第三方纯文本 URL 作为明确的来源策略；解析失败要告知用户，不作无条件全曲库可播承诺。
- 推荐：手机 UA 的网页解析可作实验支持；长期主流程仍宜用有结构化协议的推荐接口，独立验证后再加入。
- 统一数据：歌曲 ID、歌单 ID、歌手数组、歌词时间轴、请求音质、实得音质、链接获取时间及可播放状态。
- 歌单补齐：按 trackIds 分批查询，按原 ID 顺序合并，对空项容错；本次验证了 2 个 ID 的批量查询。
- 保持临时 URL 按需刷新，不能永久保存为歌曲的唯一播放地址。
- 复用浮音已有播放、音量、输出设备、悬浮窗和本地歌单控制器。API 探测成功不等于这些新入口已经集成到界面。

本轮没有实现新的主界面入口、完整歌词页、推荐页或收藏夹功能；这些仍按前一份迁移分析报告的需求清单进入后续版本。
