# 浮音 0.8 QtTest 验证记录

日期：2026-10-01。用户连接手机，并要求安装及尝试 Qt 测试。最终版本仍为 `0.8.0-preview`，Android 版本码 9，待用户体验验收。

## 结果

Windows Qt 6.11.2 / MinGW 13.1 环境的四组 CTest 全部通过：导入策略、播放器与 QML 界面、API 与歌单、单实例。默认回归未调用外部音乐服务。单独执行真实排行榜检查也通过，内置服务返回 63 个榜单，热歌榜 `3778678` 报告 200 首、读取 200 首，无不完整提示。

手机 MTN_AN80 已覆盖安装最终修复后的 ARM64 APK。系统包信息为 `versionName=0.8.0-preview`、`versionCode=9`；欢迎页成功启动，启动进程日志未检出 QML 绑定错误或崩溃。

## 发现与修复

- 电脑端歌单详情尚未加载时，导入按钮的 `enabled` 表达式会返回 `undefined`。将是否存在歌曲列表明确转为布尔值，空详情保持禁用；原有界面测试的 QML 警告断言在修复前失败、修复后通过。
- Android 欢迎页内容高度依赖 ScrollView 的可用高度，而 ScrollView 的隐式高度又由内容高度推导，切换尺寸会触发循环绑定。改为依赖欢迎窗口的固定视口高度；横竖屏测试修复前失败、修复后通过。
- 旧歌单持久化测试假定所有歌单均可删除，与 0.7 起收藏夹不可删除的功能约定不符。更新测试：删除普通歌单，保留收藏夹并验证删除被拒绝。

以上修复已编入 Windows 交付程序与重新安装的 Android APK。

## 新增检查

- 模拟服务验证内置 `/api/toplist`、自定义 `/toplist`，常见四榜优先排序、其他榜单相对顺序、去重、无效 ID/名称过滤、可选数量、无效 JSON/业务状态/结构，以及空榜单。
- 验证重复加载只发起一次请求，刷新 HTTP 503 时保留旧榜单，切换 API 清空状态并忽略旧响应。
- 验证歌单含无效或不可用歌曲时保留原始名次，显示完整数量及缺失提示。
- 加载实际 `Main.qml`，验证首次进入自动读取、再次进入复用已有列表、从榜单详情返回排行榜、四位数名次宽度、刷新失败提示、播放模式菜单位置与层级、关闭动效后按压不缩放。
- 加载实际 `AndroidMain.qml`，检查浅色/深色主题下 360×780、780×360、320×568 尺寸，验证滚动到底后退出按钮仍处于可见视口内。

## 截图与运行方式

采用 qt-testing 的离屏截图流程，适配项目的 C++ Qt Quick 架构：QtTest 创建真实 QQuickWindow，使用软件渲染与 `grabWindow()` 保存图片。没有用 QWidget 重做界面。离屏字体加载使用 Windows 微软雅黑，手机系统字体最终显示以真机为准。

已复核排行榜、榜内详情、播放模式菜单、设置和欢迎页截图。菜单显示在音乐卡片上层，四位数名次完整可见；欢迎页在小屏及横屏下允许滚动到页面底部。截图与最终测试日志保存在本地 `artifacts/qt-test-0.8/`，不随源码提交。

可在英文暂存目录的构建环境中运行：

```powershell
# 需要在 PATH 中配置对应 Qt、MinGW，并启用 FLOATMUSIC_TESTS。
$env:FLOATMUSIC_TEST_ARTIFACTS = 'C:/Temp/floatmusic-qt-screenshots'
ctest --test-dir build --output-on-failure

# 只运行真实排行榜读取检查，不执行其他联网播放检查。
$env:FLOATMUSIC_LIVE_TESTS = '1'
.\build\library_tests.exe liveRankings
```

## 未覆盖范围

QtTest 在 Windows 执行，验证共享逻辑和 QML 界面；Android 原生 Java 悬浮窗没有通过 QtTest 自动操作。本次没有实测榜内歌曲在线播放、逐档音质、系统动画开关、排序手柄和不同 Android 设备的悬浮窗口适配。手机安装和欢迎页启动成功不代表这些交互场景全部通过，继续由用户验收。
