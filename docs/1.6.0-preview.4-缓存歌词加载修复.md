# 1.6.0-preview.4 缓存歌词加载修复

## 已定位的异常路径

1. 缓存中已有完整音频，但歌词未知或之前下载失败。播放优先命中本地音频，旧实现不会再自动获取歌词，即使已经联网仍会缺词。
2. Android 的 Qt 控制器每 250ms 读取播放服务状态。旧条件把“正在获取歌词”也当作需要重新应用缓存的理由，清除加载状态并递增请求代号，导致稍后返回的有效歌词被当作过期结果丢弃。
3. Android 原生播放服务无条件用缓存歌词覆盖 Qt 状态。旧的空缓存会隐藏正在加载的状态或刚取得的歌词；桥数据缺失/属于上一曲时还可能出现“播放在线音乐后查看歌词”的默认提示。

这些路径已通过隔离数据复现；用户报告没有固定复现步骤，不能据此排除其他网络服务或设备相关原因。

## 修复

- 播放只有音频的缓存时异步补取歌词，不阻塞音频起播。Windows 的补取与手动刷新均通过缓存模块保存结果，保留每个缓存项目的请求代号与切歌隔离。
- Android 仅在歌曲或缓存歌词内容/状态实际变化时应用缓存，不再因为定时轮询清除正在进行的请求；访问时间、下载进度等变化不会触发歌词重置。空的失败侧写也不会打断已有请求。
- 当前歌曲的 Qt 加载状态、错误和新歌词优先，旧空缓存不再覆盖它们。收到上一曲的桥数据时不显示旧歌词；在线曲目显示“正在获取歌词…”，本地导入音乐仍保留原有提示。
- 已有完整歌词的缓存不会因此在每次播放时重新联网。明确标记无歌词的纯音乐不会自动反复请求；失败后仍可手动刷新。

## 验证

- Windows 缓存缺词用例：修复前播放成功但歌词断言失败；修复后自动获取原文和译文并通过手动刷新检查。
- 缓存侧写轮询用例：重复轮询、访问时间变化、请求中收到空失败侧写均不会重新覆盖当前请求；新歌词可以正常应用。
- Android 原生覆盖回归：旧代码在“空缓存不能隐藏在线请求”断言失败；修复后完整 83 项原生检查通过，包括恢复的新歌词、上一曲状态隔离、原有离线播放/进度/双语歌词/音质/删除/手动保存功能。
- 原生检查使用专用模拟器，不修改用户音乐数据。最终构建记录保存在 `artifacts/v1.6-lyrics-fix/`。
- 最终 Windows 完整 CTest **16/16 组通过**，缓存播放控制器 **9 项通过**（父进程跳过子进程专用槽，实际重启子进程通过）；Android ARM64 安装包签名、版本码及 **93 文件源码快照**核对通过。
