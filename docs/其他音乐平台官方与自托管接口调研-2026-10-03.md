# 其他音乐平台 API 接入浮音可行性调研

调查日期：2026-10-03（Asia/Shanghai）。对象：浮音的 QQ 音乐、酷狗、酷我与补充 JOOX 接入选择。代码基线：`6a238786fea3181f8927bcf59bf51663b21535d2`，双端 0.8。

本文是 0.8 基线上的历史调研。后续匿名实测见[第三方接口报告](匿名第三方音乐接口候选-2026-10-03.md)；双端 0.9 已接入 QQ、酷我歌曲库，当前功能见[双端验收说明](双端-0.9-验收说明.md)。

本次阅读官方页面、项目作者文档、源码与实际提交记录，并对现有聚合服务做少量匿名 HTTP 样本检查。音频检查最多读取 64 字节头部，没有下载整首歌曲、解码试听、登录账号或使用用户 Cookie；自托管候选未安装运行。下文明确区分“文档支持”“匿名样本响应”和“浮音接入判断”，不能把非空 JSON、URL 或音频头部当成完整可播证明。

## 结论与选择顺序

1. **正式授权路线确实存在。** QQ 音乐开发者平台、腾讯云 IoT 音乐服务和酷狗曲库开放组件都有一手证据；它们有合作方、应用/设备授权、SDK 场景或计费条件。本轮未找到一套明确允许普通个人 Windows + Android 独立播放器任意匿名使用的官方通用搜索、歌单、歌词、音频 REST 接口。这里的结论是“未找到适用证据”，不是“平台不存在官方 API”。
2. **QQ 音乐优先评估 `L-1124/QQMusicApi`。** 它是近期维护的 Python 库，并提供可自托管 HTTP 服务；搜索、歌单、歌词与音频 URL 都有源码。音频取得仍依赖登录与上游授权结果。`jsososo/QQMusicApi` 可作协议与旧适配参考；`copws/qq-music-api` 不宜当完整服务或直接分发依赖。
3. **酷狗优先评估 `MakcRe/KuGouMusicApi`。** 它近期维护、MIT、已有完整 Node HTTP 服务与文档，但当前文档明确写了搜索认证、设备指纹与音频加密等条件。不能按“无需账号即可稳定搜索和播放”的服务设计。
4. **酷我暂列后续候选。** 已发现腾讯云 TME 体系包含酷我服务提供商；单独的旧 `qyhqiu/kuwoMusicApi` 有相关能力，但最后代码提交在 2023 年，缺少今日可用性证据。

5. **现有 GD 服务不能直接打开 QQ、酷狗或酷我曲库。** 本次三个来源的搜索均返回 HTTP 400、不支持 source；INJAHOW 的公开 QQ 样例则取得了曲目信息、逐句歌词与 MP3 头部，但没有搜索功能，还有 HTTPS → HTTP 跳转问题。JOOX 搜索成功，但所查音频地址为空，暂不能列为可用播放来源。
6. **扩大音乐池需要增加“音乐平台”适配。** 当前 GD、原接口和 INJAHOW 都在解析网易云 ID，作用是给同一曲库增加音频提供方。新增平台涉及两端搜索、歌词、播放、收藏、歌单导入导出和恢复现场，不能只更换一个接口地址。

以上顺序是基于资料完整度、维护记录、匿名样本和代码审阅的工程判断，不是端到端播放实测排名。建议优先验证 QQ 的搜索、公开歌单、歌词与普通音质闭环；酷狗作为第二候选；酷我与 JOOX 暂保留。具体依据见下面各节。

## 现有公共服务的匿名样本

采样时间：2026-10-03 14:33–14:45（北京时间）。网络为本机已配置的系统代理，未携带个人 Cookie；结果只代表该时间、出口和所查曲目。没有用重试次数估计长期成功率，也没有推断整个平台全部曲目能否播放。

### GD 音乐台：QQ、酷狗和酷我当前未开放

[GD 作者接口说明](https://music-api.gdstudio.xyz/api.php)的当前更新日期为 2026-09-16，稳定源列为 `netease`、`joox`、`bilibili`；参数列表虽包含 `tencent` 和 `kuwo`，同时说明部分来源不开放。当前参数列表没有 `kugou`。声明限制为 50 次 / 5 分钟，非商业学习用途及注明 GD 音乐台出处；文档标注 CC BY-NC 4.0，并限制下载、传播。接入时须核对用途，不能把“多源参数列表”视为实时可用名单。

对照请求为 `types=search`、`name=海阔天空`、`count=3`、`pages=1`，只改变 `source`：

| 来源 | HTTP 与结果 | 可以得出的结论 |
| --- | --- | --- |
| `netease` | 200，3 首 | 同一网络下对照请求成功 |
| `tencent` | 400，不支持 source | 当前 GD 不能承担 QQ 搜索 |
| `kugou` | 400，不支持 source | 当前 GD 不能承担酷狗搜索 |
| `kuwo` | 400，不支持 source | 当前 GD 不能承担酷我搜索 |
| `joox` | 200，30 首 | 搜索响应成功；实际返回数量不遵守本次 count=3 |

对三个 400 来源分别补查了一次错误正文，均为 `Value of source is not supported.`。这是服务的参数拒绝，不是 QQ、酷狗或酷我整个生态不存在可用接口，也不支持靠不断重试解决。

JOOX 另查 Beyond《海闊天空》的第一个结果（ID `_XOgoxayHDWFwj1IqY3B6A==`）：320、128、999 三种请求均为 HTTP 200、空 `url`、`br=-1`、`size=0`；第二个结果的 320 请求也是空地址。首曲歌词返回 1015 字且有 LRC 时间戳。因此目前只确认搜索和该曲歌词响应，**没有确认 JOOX 播放链路**。ID 包含 `+`、`/`、`=` 等字符的潜在编码问题，也要求保留原始字符串并正确 URL 编码。

### INJAHOW：QQ 的小范围证据较好，不能负责搜索

[INJAHOW 接口说明](https://api.injahow.cn/meting/index.php)列有 `netease`、`tencent` 与曲目、歌单、音频、封面、歌词等类型，没有搜索或排行榜接口。[服务入口源码](https://github.com/injahow/meting-api/blob/master/index.php)按类型白名单处理；其曲目响应是 `name/artist/url/pic/lrc`，需由调用方保留平台原始 ID。音频请求固定调用库的 320 档，不能将浮音的 Hi-RES 选项直接解释成它会返回 Hi-RES。

使用 [MetingJS 作者公开示例](https://github.com/metowolf/MetingJS)中的 QQ `songmid=001RGrEX3ija5X`，请求 `server=tencent&type=song`：

| 检查 | 本次响应 | 验证范围 |
| --- | --- | --- |
| 曲目信息 | HTTP 200，杨宗纬《星》，音频及歌词回调非空 | 一个 QQ 曲目能查询到元数据 |
| 歌词 | HTTP 200，915 字，有时间戳 | 可适配浮音现有逐句歌词解析 |
| 音频回调 | HTTPS 302 → `http://aqqmusic.tc.qq.com`，Range 请求 206、`audio/mpeg`、64 字节以 ID3 开头；Content-Range 总长度 4,072,780 字节 | 响应确实包含 MP3 头部；未验证完整解码、时长、试听限制或实际音质 |
| 同一 CDN 地址改用 HTTPS | 同样返回 206、MP3 头部与相同总长度 | 这个样例的 CDN 支持 HTTPS；不能推广为任意返回地址均可直接改协议 |

现有浮音的 C++ 与 Android 解析器都禁止 HTTPS 降级重定向，原样接入该回调会失败。可行处理是适配层在允许的 CDN 范围内验证 HTTPS 地址，再交给播放器；需要中转时另行核对服务条款与部署成本。**不建议全局放开降级跳转或关闭 TLS 验证。** INJAHOW 可作为 QQ 已知 MID 的候选音频/歌词提供方，仍需另一个后端提供搜索、歌单发现与稳定 ID。

### Meting：统一后端候选，不等于所有平台已验证

[metowolf/Meting](https://github.com/metowolf/Meting)当前是 `@meting/core` 的 Node.js 实现，提供跨平台搜索、曲目、歌单、URL、歌词和封面。平台支持表包含网易云、QQ、酷狗、酷我等；标准化结果保留 `source`、`id`、`url_id`、`lyric_id`。代码为 MIT，实际默认分支最后提交为 [1c2f4c9](https://github.com/metowolf/Meting/commit/1c2f4c98eed749200d9d7ff5cab329c4308f4268)，2026-02-27；该提交添加酷狗带 Cookie 的新签名接口与旧接口降级。没有运行该库，本轮不能给这些支持项标注“今日实测可用”。

[metowolf/Meting-API](https://github.com/metowolf/Meting-API)可把核心库包装成共用 HTTP 服务，提供缓存、Cookie 配置与资源回调签名，接口形态对浮音适配较省事。当前 [package.json](https://github.com/metowolf/Meting-API/blob/0f5a5cbbd0aef723bd3bbdabf7c3b35c8354a678/package.json)声明 MIT、以 Bun 启动，[入口源码](https://github.com/metowolf/Meting-API/blob/0f5a5cbbd0aef723bd3bbdabf7c3b35c8354a678/src/index.js)使用 `Bun.serve`；README 仍保留 Hono 的旧表述，部署以源码为准。默认分支最后提交为 [0f5a5cb](https://github.com/metowolf/Meting-API/commit/0f5a5cbbd0aef723bd3bbdabf7c3b35c8354a678)，2026-03-08。其列表使用 `title/author` 及资源回调，与 INJAHOW 的字段不同，仍需适配。

工程取舍：Meting 适合尽快试验一个统一的多平台后端；L-1124 与 MakcRe 的平台专用实现，文档和认证能力更完整、修复记录更近。建议先做 QQ 闭环并保留替换后端的接口，不能为省一个适配器而把全部平台绑定到同一公共服务。

## 官方接入渠道

### QQ 音乐

- [QQ 音乐开发者平台](https://y.qq.com/music_developer/)与[开发者平台入口](https://developer.y.qq.com/)列有登录鉴权、OpenAPI、车机与大屏等方案；公开介绍将 QPlay Auth 描述为用户对合作方产品授权、使用在线服务及个人权益的路线。这能证明官方合作能力存在，尚不足以确认浮音这类个人独立播放器的准入、定价和完整平台支持。
- [腾讯音乐官方 QPlay OpenAPI 示例](https://github.com/tencentmusic/QQMusic_Innovation_QPlay_OpenAPI_Demo/blob/partner/README.md)要求应用 ID/Key/私钥、硬件注册参数由 OpenAPI 管理方提供；合作伙伴还需要设备凭据与 QQ 音乐 OpenID/Access Token。示例包含个人歌单目录和歌单详情。这属于有合作方和设备身份的接入示范，不能将示例中公开的旧参数用于浮音。
- [腾讯云物联网开发平台“音乐服务”](https://cloud.tencent.com/document/product/1081/67456)明确提供 QQ 音乐搜索、歌单、歌词、歌曲信息与播放链接。调用入口属于腾讯连连自定义 H5 SDK，常规接口须完成 QQ 音乐账号授权；免登录专区另有指定歌曲列表与 SongToken 流程。**这是 IoT/H5 面板场景的官方能力证据，普通 Windows/Android 播放器的直接准入仍未确认。**
- [QQ 音乐移动 WEB 开放说明](https://y.qq.com/m/api/open/index.html)提供 QMplayer 播放组件，使用歌曲 MID，且可拉起 QQ 音乐客户端；它不能直接替代浮音所需的通用搜索、歌单、歌词、可解码音频后端。本轮未验证这个旧组件在当前客户端中的运行效果。

对浮音的判断：如果要走可长期约定的官方路线，应先由平台确认个人开发者准入、独立播放器场景、Windows 与 Android 支持以及账号权益使用范围；现有证据不能把官方合作渠道直接变成匿名备用源。

### 酷狗

- [酷狗曲库开放计划](https://open.kugou.com/docs/open-player/)公开介绍 Android/iOS SDK、在线播放与按有效播放计费；应用页面需标注酷狗技术支持。[应用信息页面](https://open.kugou.com/mini/mini_detail)还列有应用平台、审核状态、appid 与 appkey 字段。它是正式 SDK 产品路线，本轮未找到相应的通用 Windows 原生 REST 播放授权说明。
- [酷狗官方商务合作页](https://www.kugou.com/about/business.html)介绍 mini 酷狗的搜索、播放集成，以及车载 APK/SDK 和酷狗小程序合作；这些入口与直接提取官方网页内部音频链接并不是同一种接口契约。
- [腾讯云“音乐服务 SDK”](https://cloud.tencent.com/document/product/1081/68800)提供酷狗授权、`requestTMEApi(action, params, deviceId)`、歌曲详情和歌单详情；以已初始化 IoT 应用 SDK 或 H5 面板为入口，并需要设备身份。它可以作为官方设备接入路线，不足以证明任意个人播放器可以直接复用。

对浮音的判断：Android 若接受 SDK、申请和计费，可进一步核对曲库开放组件；Windows + Android 共用一套匿名音频 REST 方案，当前官方证据不足。

### 酷我与共同的权益限制

[腾讯云 TME 数据结构](https://cloud.tencent.com/document/product/1081/40780)的服务提供商字段包含酷狗、酷我和 Q 音，不能据此说酷我没有官方接口。该体系还明确区分可播放、地区限制、无版权、非会员、需购买、设备版权限制等状态；应用能播放某曲不代表另一个设备或产品也有播放权。

本轮未找到适用于普通个人独立 Windows/Android 播放器的酷我公开完整接入说明，也未取得合作准入或具体动作覆盖的确认。对酷我的官方路线只能保留“需平台确认”，不能从网上的内部接口地址推导出官方开放授权。

## QQ 自托管接口的详细条件

### L-1124/QQMusicApi

**覆盖与部署形态。** [快速开始](https://github.com/L-1124/QQMusicApi/blob/main/docs/tutorial/start.md)说明可直接使用 Python 包；[Web 服务说明](https://github.com/L-1124/QQMusicApi/blob/main/docs/tutorial/web.md)提供自托管 HTTP 服务与 OpenAPI 文档。搜索有歌曲、歌手、专辑、歌单、MV 等类型；歌单读取按页返回歌曲；歌词包含普通歌词、逐字歌词、翻译等参数；歌曲链接另有 CDN 与音质过程。源码：[search.py](https://github.com/L-1124/QQMusicApi/blob/main/qqmusic_api/modules/search.py)、[songlist.py](https://github.com/L-1124/QQMusicApi/blob/main/qqmusic_api/modules/songlist.py)、[lyric.py](https://github.com/L-1124/QQMusicApi/blob/main/qqmusic_api/modules/lyric.py)、[song.py](https://github.com/L-1124/QQMusicApi/blob/main/qqmusic_api/modules/song.py)。

**ID 类型。** 歌曲有数值 `songid/id` 与字符串 `songmid/mid`；详情和歌词支持 ID 或 MID，URL 构造使用 MID，部分文件名还依赖 `media_mid`。歌单使用数值 `songlist_id`，发往上游的字段为 `disstid`。这些 ID 不可直接当作网易云歌曲 ID，也不宜只保留一个没有平台/类型的通用字符串。依据为上述歌曲、歌词与歌单源码。

**登录与 Cookie。** [凭据说明](https://github.com/L-1124/QQMusicApi/blob/main/docs/tutorial/credential.md)将 `musicid` 与 `musickey` 列为核心凭据，另有刷新字段；[Web 服务说明](https://github.com/L-1124/QQMusicApi/blob/main/docs/tutorial/web.md)规定这两个 Cookie 字段必须同时提供，完全不带 Cookie 时以未登录状态请求。部分公开接口可不登录，不等于所有元数据或音频可匿名取得。凭据过期、账号登录方式和 Android 匿名设备会话是需要维护的独立状态。

**签名与设备。** [执行器源码](https://github.com/L-1124/QQMusicApi/blob/main/qqmusic_api/core/executor.py)会为需要签名的请求使用内置 `zzc_sign`，并处理 Android 会话、QIMEI 与对应 Cookie。这是第三方库对内部请求协议的实现；不是浮音已经取得正式 OpenAPI 应用凭据。自托管能控制进程和缓存，但不能消除上游协议更新或设备风控条件。

**音频与会员。** [下载/文件链接文档](https://github.com/L-1124/QQMusicApi/blob/main/docs/tutorial/download.md)明确要求登录凭据，并提供付费播放、付费下载、会员字段与 URL 授权结果码：成功、无权限、VKey 失败、设备受限分别需处理。返回可用音质字段也不等于当前账号拥有该音质。源码还有普通、试听和加密文件类型；本轮没有解密或会员曲解锁试验。

**推荐度。** 对拥有 Python 客户端或愿意单独运行 Python HTTP 服务的浮音，这是目前最值得先做有限验证的 QQ 候选。它有近期提交、结构化模型与较完整文档；仍应先验证匿名搜索/公开歌单/歌词，再在用户明确授权后验证其本人的正常账号权益。资料阶段不能承诺免费完整播放、长期可用或 Windows/Android 播放器对每种格式均可解码。

### jsososo/QQMusicApi

[作者文档](https://github.com/jsososo/QQMusicApi/blob/master/docs/README.md)已有 `/search`、`/songlist`、`/lyric` 与 `/song/urls` 等能力，并写明歌曲 ID、MID、歌单 ID 等参数差异。部分请求依赖登录 Cookie；音乐链接依账号和会员权益决定，旧文档还讨论服务器预存 Cookie 与公共 Cookie 的账号风险。作者的公共示例或旧文字不能证明自行部署后在无 Cookie 情况下可以播放。

[README](https://github.com/jsososo/QQMusicApi/blob/master/README.md)支持 Node、npm 与 Docker，服务形态便于接入，但默认分支最后提交是 2022 年。建议把它作为旧 QQ 返回结构和参数的对照，若采用需重新验证搜索与 VKey 链路，不能以未归档或近期 Star 活动代替维护证据。

### copws/qq-music-api

[README](https://github.com/copws/qq-music-api/blob/main/README.md)宣称 2025-09 重新更新音频 URL，包含搜索、歌单、歌词、专辑等异步函数；[JS 源码](https://github.com/copws/qq-music-api/blob/main/qq-music-api.js)对部分 fetch 使用 `credentials: "include"`。源码存在并不证明浏览器会带上正确 Cookie，更不证明跨域请求成功。

该仓库只有 README 与 JS，没有自托管服务、完整登录/刷新管理或 LICENSE。本轮不将其列为可直接安装并分发的 API 后端；作者 2025 年确认可用是历史自述，不能作为 2026-10-03 的播放验证。

## 酷狗自托管接口的详细条件

### MakcRe/KuGouMusicApi

**覆盖与部署形态。** [README](https://github.com/MakcRe/KuGouMusicApi/blob/main/README.md)列有搜索、歌单、歌词、音频 URL、登录与刷新等能力；已有 Node HTTP 服务与自部署说明。README 的运行门槛为 Node 12+，[package.json](https://github.com/MakcRe/KuGouMusicApi/blob/main/package.json)含启动和 Windows 打包脚本，这只能证明作者提供此形态，不能证明其二进制适配浮音或 Android 的运行环境。两端通过自托管 HTTP 后端访问是可评估形态。

**ID 类型。** 音频通常使用歌曲 `hash`，并可能携带 `album_id` 与 `album_audio_id`；歌单详情/歌曲接口使用 `global_collection_id` 字符串，部分新版使用 `listid`；歌词不是直接以歌曲 ID 下载，需要先取得歌词 `id` 与 `accesskey`。这些字段应分别保留，不能将不同 ID 或不同音质 hash 混用。来源：[作者接口文档](https://github.com/MakcRe/KuGouMusicApi/blob/main/docs/README.md)、[音频 URL 源码](https://github.com/MakcRe/KuGouMusicApi/blob/main/module/song_url.js)。

**搜索认证。** [作者接口文档的搜索章节](https://github.com/MakcRe/KuGouMusicApi/blob/main/docs/README.md#搜索)明确写明需认证 Cookie，否则可能返回 `error_code: 152`，并建议所有搜索接口携带认证；示例字段有 `token`、`userid` 与 `dfid`。这是需要登录/设备条件的候选，不能把 README 的“搜索”功能列表解释成匿名可用。

**签名、设备与平台模式。** [请求器源码](https://github.com/MakcRe/KuGouMusicApi/blob/main/util/request.js)从 Cookie 提取账号和设备信息，生成 Android/Web 等签名；搜索模块使用 Android 请求模式。README 提示常规版与 `platform=lite` 概念版 token 不通用。自托管需要将账号/设备状态与平台模式一致维护，签名过程由库实现仍可能随平台变化失效。

**音频、会员与加密。** [作者文档“获取音乐 URL”](https://github.com/MakcRe/KuGouMusicApi/blob/main/docs/README.md#获取音乐-url)写明未登录或非会员可能为空，以及需要设备 `dfid` 的验证条件。新版 URL 文档还警告部分音频加密、作者当前不能解码；有 URL 不等于播放器能够读取音频。[song_url.js](https://github.com/MakcRe/KuGouMusicApi/blob/main/module/song_url.js)包含音质与试听参数。文档另有 Auth 路线的普通音质可用性自述，本轮没有执行或验证，不能推广为所有账号/歌曲皆能完整播放，更不能作为付费内容解锁承诺。

**歌词。** [search_lyric.js](https://github.com/MakcRe/KuGouMusicApi/blob/main/module/search_lyric.js)按关键词或 hash 搜索歌词候选，[lyric.js](https://github.com/MakcRe/KuGouMusicApi/blob/main/module/lyric.js)用歌词 `id` 与 `accesskey` 下载，可返回 LRC/KRC 并按参数解码。客户端还需要匹配候选与时间轴，不应把任一搜索候选直接当目标版本歌词。

**推荐度。** 源码与文档较完整、2026-10 仍有实际提交，适合先评估元数据和歌词功能，再在正常账号权益范围内评估音频。对浮音而言主要障碍是认证状态、设备状态、歌曲版本/音质 hash 选择，以及返回音频的格式和加密状态。本轮没有服务启动、匿名接口样本或音频验证，因此没有“实测可用”的结论。

### 数据与服务边界

1. **分开音乐平台和音频提供方。** 曲目平台是 `netease/tencent/kugou/kuwo`；GD、INJAHOW、自托管库是提供方。当前 `MusicApi::Audio.sourceId` 表示提供方，不能直接拿它代替歌曲平台。备用链应以“同一平台、同一曲目、不同提供方”切换。
2. **使用平台原始 ID，保留相关引用。** 全局键可表达为 `平台:原始ID`，原始 ID 按字符串保存；另存 ID 类型、媒体引用、歌词引用与必要的设备/授权状态。QQ 的 songmid、songid、media_mid 和酷狗的 hash、album_audio_id、歌词 accesskey 都不能互相替代。酷狗不同音质 hash 也不宜变成收藏中的多首重复歌曲。
3. **播放地址到播放时再解析。** 收藏、导出和恢复主要保存稳定身份及元数据，不保存长期有效的 vkey、临时音频地址或个人凭据。恢复播放时按平台取得新地址，再恢复位置。音质列表应反映该平台与账号真正支持的档位，不能统一承诺 Hi-RES。
4. **账号与设备状态放在明确的服务边界。** 若采用 Python/Node/Bun 后端，两端通过规范化 HTTPS 接口使用；不用把这些运行时直接塞进 Android 播放客户端。电脑上的 localhost 不等于手机上的 localhost：双端需共用可达服务，或分别实现原生适配。自托管改善可维护性和请求控制，不会解除上游风控、权益或加密限制。
5. **失败信息区分原因。** 空地址、未登录、会员/地区限制、服务维护、限流、加密格式和解码失败应单独呈现；对 source 不支持和无权限错误停止无意义重试。可沿用现有超时、取消、冷却和有限备用机制，但按平台与提供方管理。

搜索页可以保留紧凑的来源选择，结果显示平台标识；先按指定平台搜索，后续再聚合。聚合结果可以按歌名、歌手、专辑、时长分组展示不同版本，但保留各自平台身份。**不建议根据同名自动把网易云收藏替换成 QQ 或酷狗曲目**，否则 Live、翻唱、重制版、伴奏或歌词时间轴可能错配。
