# Android 1.4.0-preview.1 歌词修复

版本码 20，同签名覆盖安装；原歌单和设置继续保留。此修订同时处理独立透明悬浮歌词的跳动和播放器内部歌词的切句跟随。

## 问题与修复

- 独立歌词原先按屏幕上的第几个位置复用窗口，整数句号变化时，仍在显示的窗口被改成另一句文字。不同文字宽度与窗口边界更新叠加，产生横向闪动。现在每句歌词在可见期间保留自己的窗口，新窗口直接以最终位置和大小加入系统。
- 进入视野的长歌词原先会推动整组歌词的水平中心。现在保持用户拖放的锚点，长句根据锚点两侧的空间适配，不移动其他歌词。
- 与歌词无关的界面数据刷新原先会重置滚动进度。现在只在曲目或实际歌词数据变化时重置；普通状态刷新保留动画中的位置。
- 播放器内部在第一句、第二句等靠近列表边界的位置缺少滚动空间，切句的目标位置始终为零。现在首尾保留居中空间，每句都可滚动经过阅读位置；字号高亮完成布局后再计算目标，取消过时的滚动请求。
- 手动翻看仍暂停跟随，返回箭头恢复；关闭界面动效时直接定位，不添加额外动画。

## 验证方式

先在旧代码上运行隔离 Android 原生测试，实际触发窗口身份变化、水平锚点移动、刷新打断动画，以及前两句位置均为零；失败记录位于 `artifacts/android-lyric-jump-2026-10-20/red-all-192038/`。

随后以真实生产 Java 代码、真实 `WindowManager`、View、字体测量和系统动画，在 Android API 36 x86_64 模拟器运行。测试包使用独立包名 `org.floatmusic.lyricfixture`，不启动 Qt 主界面或音频服务，不读取用户歌单；本次未连接或修改用户手机。

复现命令：`./tests/android/run-lyric-regression.ps1 -DeviceSerial emulator-5580 -Label final`。脚本仅接受本地模拟器序列号，结果与截图保存到 `artifacts/android-lyric-jump-2026-10-20/`。

最终八个原生界面场景全部通过：开关动效下独立歌词窗口保持身份、长句不移动水平锚点、无关刷新不打断动画、播放器长距离跟随、开头相邻句跟随、手动翻看与返回，以及关闭动效后的直接定位。结果与八张实际截图在 `artifacts/android-lyric-jump-2026-10-20/final-192812/`。

播放器首两句的滚动中间帧记录为 `[12, 17, 19, 21, 23, 25, 26, 27, 28, 29, 30, 31, 32, 33]`，关闭动效后的同类长距离切换为 `[75, 369]`。无关刷新前后的独立歌词动画进度均为 `3.6232853`，没有被强行跳到下一整数句。

最终七套离线规则/语言/队列/通知回归通过，日志位于 `artifacts/v1.4.0-preview.1-android-2026-10-20/tests/contracts/20261020-192840/`。已再次核对全部 87 个生产源码文件与 APK 构建快照一致，APK 哈希一致。
