# Android 1.4.0-preview.3 真机动效优化

版本码 22。针对独立悬浮歌词切换拖沓、上下滚动卡顿，以及播放器内部歌词滚动卡顿。用户确认长短句都会卡，横向跳动已修复。本次保留现有页面和横向锚点，不修改电脑版。

## 原因与改动

1. 独立歌词虽然已统一绘制，仍要在动画帧移动多个原生触摸窗口。用户手机上六次普通切句共调用 178 次窗口位置更新，绘制回调间隔的第 95 百分位约 72ms。Android 13+ 改用公开的 `AttachedSurfaceControl.setTouchableRegion`，只保留一个窗口，每帧更新紧贴文字的触摸区域。行间与周围留白仍可穿透，Android 9–12 保留原有逐行触摸窗口作为兼容路径。
2. 独立歌词原为 420ms 的缓慢起步曲线；两处现在统一为 260ms、与电脑版 OutCubic 同形的快速起步和缓慢收尾曲线。当前句的高亮和缩放连续变化。
3. 播放器原用整数像素滚动，减速尾段可能隔几帧才前进一像素。单独采样时屏幕帧回调约 16.7ms，歌词绘制间隔却约 67ms。现在使用浮点动画，通过内容层位移保留小数像素；结束、取消或手动翻看时清理余数。
4. 播放器高亮原会改字体和字号，让整列重新测量。现在按高亮所需字号一次排版，用绘制缩放和加粗切换状态。长句换行保持稳定，行内保留最大字高，避免放大裁切或挤动邻行。
5. 手动翻看后返回当前句，原来的 `fling(0)` 并不会立即终止系统滚动，仍可能覆盖自动跟随的位置，关闭动效时尤为明显。现在由手动浏览和自动跟随分别控制位置，自动跟随时不推进残留原生惯性。触摸、无障碍翻页、键盘和滚轮都会先接管为手动浏览，返回箭头再恢复跟随。

## 复现与验证记录

- 修复前真机采样：`artifacts/android-lyric-jump-2026-10-20/phone-pacing-red-213847/`。独立歌词绘制间隔 p95 为 72.39ms，播放器为 67.25ms；两处在 320ms 内均未稳定完成每次切句。
- 只替换独立歌词触摸窗口后的对照：`phone-region-probe-214056/`。动画时长暂未改动，绘制间隔 p95 已降为 17.81ms，窗口位置更新降为零；拖动与留白透传通过。时间检查仍失败，证明窗口开销和动画节奏是两个独立问题。
- 播放器排查：`phone-player-layout-red-214148/`、`phone-player-clock-red-214320/`，覆盖高亮造成的整列高度变化，以及稳定帧回调下的整数滚动停顿。
- 浮点滚动和时长修改后：`phone-pacing-green-214407/`。独立歌词 p95 为 17.93ms，播放器为 18.59ms，六次切句均在 320ms 检查点前结束；160ms 时平均完成约九成位移。
- 长双语文本的裁切测试先失败于 `phone-long-bounds-red-214551/`，预留高亮字号后通过于 `phone-long-cross-green-214713/`。该轮跨应用触摸测试因 Instrumentation 限定输入 UID 而失败，改用 UiAutomation 的系统输入注入后，真实跨 UID 透传与拖动通过于 `phone-layout-sequence-215404/`。

上述目录均在 `artifacts/android-lyric-jump-2026-10-20/` 下。绘制间隔来自真实原生 View 的回调，并同时记录 Choreographer 帧回调，不能等同于所有设备上的固定呈现帧率。

首轮完整真机回归 `phone-final-native-215506/` 为 **19/19 通过**：三行独立歌词绘制间隔 p95 为 17.07ms，九行为 9.33ms，播放器普通句为 21.39ms、160 行长双语文本为 20.97ms。各六次切句均在 320ms 检查点前完成，独立歌词动画期间零窗口位置更新，播放器文字内容高度零变化。手机自适应刷新率在 60/120Hz 间切换，因此两种间隔不直接作为恒定帧率比较。

前一次完整回归 `phone-full-native-214816/` 为 18/19，失败项 `player-frame-pacing` 将两次窗口尺寸变化也计为歌词内容重排。后续补充逐行及内容高度采样，将视口居中留白与歌词内容高度分开检查，最终完整回归通过；没有通过放宽文字内容高度检查来掩盖高亮重排。帧间隔预算为两次 60Hz 刷新加采样容差（35ms），同时保留原始记录。

安装后原有八项界面检查两次出现 7/8，均失败于 `lyrics-small` 的手动返回。将等待主线程空闲改为等待实际居中后仍失败（位置 0、目标 2309），确认并非单纯测试过早。新增原生场景 `player-no-motion-return` 在 `phone-no-motion-return-red-220146/` 复现失败，控制滚动所有权后在 `phone-final-twenty-220251/` 的 20 项回归全部通过。代码复核进一步发现非触摸浏览入口需要接管；`phone-accessible-red-220449/` 记录修复前失败，随后补齐无障碍、键盘与滚轮入口。

最终源码的 `phone-final-twenty-one-220622/` **21/21 通过**，包含关闭动效后返回及真实无障碍、键盘浏览。三行／九行独立歌词 p95 分别为 17.66／15.93ms，播放器普通／长双语为 19.47／19.73ms；四组均在 320ms 检查点前完成所有六次切句。两处文字内容高度和独立歌词窗口位置更新均为零变化。

测试只使用隔离设置与合成歌词，不请求音源或操作用户歌单。跨应用背景是另一独立 UID 的临时测试应用。Android 9–12 兼容路径本轮未在对应系统真机测试。
