# Android 1.4.0-preview.2 滚动优化

版本码 21。重点处理用户继续反馈的独立透明悬浮歌词上下滚动发卡。保留现有布局、行数、明暗模式、位置保存与手动拖动；电脑端不变。

## 原因与修改

上一版验证了窗口身份和最终位置，却没有覆盖每一帧的绘制开销。新增原生采样后发现，一次切句会造成 14～17 次可见文字窗口尺寸重排；位于中央的旧当前句在动画起点还会从 31.36 突然切为 28 的字号。

这次改为单一硬件加速绘制层，滚动位置使用浮点坐标。普通与高亮文字分别缓存，动画帧只做缩放、透明度和高亮合成，不重新测量、栅格化或调整可见绘制窗口的大小。高亮和大小按离阅读中心的距离连续变化，420ms 曲线平滑起步与收尾。

文字大小的透明触控窗口独立维护，限制更新频率，动画结束后精确同步。它们不绘制任何内容，保留文字拖动；统一绘制层不接收触摸，Android 12+ 使用系统允许的最大遮挡透明度，支持留白透传。停在同一句时，播放进度的普通刷新不再唤醒绘制层。

## 验证记录

- 修复前：`artifacts/android-lyric-jump-2026-10-20/smooth-red-210512/`。新增的文字突变与可见表面重排两个场景失败；采样为 `31.36 -> 28.0`、14～17 次重排。
- 修复后：`artifacts/android-lyric-jump-2026-10-20/smooth-final-212245/`。13 项原生界面场景全部通过，三行和九行均为 `31.36 -> 31.36`、0 次可见绘制表面重排，且硬件合成已开启。
- 触摸场景在受控背景 Activity 上实际注入点击和拖动，检查文字接收触摸、行间空白到达背景、拖动不误点背景。测试包与数据独立于用户的浮音安装和歌单。
- 另覆盖无关刷新不打断滚动、水平锚点稳定、静止不重绘、播放器内部切句、手动返回和关闭动效时直接定位。
- 模拟器的软件图形后端曾导致主机 qemu 进程崩溃；最终使用主机 GPU、禁用 Vulkan 的后端完成验证。环境失败不计入通过记录。

复现入口：`tests/android/run-lyric-regression.ps1 -DeviceSerial emulator-5580 -Label smooth-final -AdbPort 5041`。默认 ADB 端口仍为 5037；本次用独立服务端口 5041。

这些结果证明绘制路径的重排和字号突变已消除，不代表已经测得所有手机上的固定帧率。后续仍需在用户手机上确认长短句交替、多行歌词、拖动后连续播放，以及其他应用背景下的实际手感。
